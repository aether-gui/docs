## What you'll do

Power the machine on, answer the short setup screen, and wait for the platform bootstrap that runs
in the background. About 12 minutes, most of it waiting.

## Prerequisites

- The [install](/docs/iso/install/) finished and the machine powered itself off.
- The USB stick is removed, or the virtual media detached.

## What happens

Two things start on the first boot:

- **The platform bootstrap.** A service unpacks the bundle staged by the installer and installs
  Kubernetes (RKE2), Helm, the Aether container images, OnRamp, and `aether-ops`. It runs
  unattended and took just under ten minutes on the lab machine. Its progress shows only as
  ordinary service messages on the console.
- **The setup screen.** About a minute after boot, a text dialog titled *Aether Node Setup* appears
  on the console and asks for a hostname and network settings. You can answer it while the
  bootstrap is still running.

## Steps

<Steps>

1. **Power the machine on.** It boots from its disk into Ubuntu. The hostname is derived from the
   first network card's MAC address, for example `aether-80fd87`, until you change it.

2. **Answer the setup screen.** Use the arrow keys, Tab, and Enter. Boot messages keep printing
   for a while and can scribble over the dialog; it still responds, and the next screen redraws
   cleanly.

   <Image src={welcome} alt="The Aether Node Setup welcome dialog" />

   - *Welcome* lists what will be configured. Choose **Yes**.
   - *Hostname* offers the generated name; type a better one if you like.

     <Image src={hostname} alt="Hostname dialog with aether-lab typed in" />

   - *Topology* asks whether one network card carries everything (**collapsed**) or the
     management, N2, N3, and N6 networks have their own cards (**separated**). For a first
     single-machine network choose collapsed.

     <Image src={topology} alt="Topology dialog offering collapsed or separated" />

   - For each interface, choose which card to use, then **DHCP** or a static address and gateway.

     <Image src={ipMethod} alt="IP configuration dialog offering DHCP or static" />

   - A summary confirms what was written.

     <Image src={summary} alt="Setup Complete dialog showing the hostname and network mode" />

   The choices go to `/etc/netplan/90-aether.yaml` and are applied immediately. Run
   `sudo aether-setup` at any time to change them.

3. **Wait for the bootstrap to finish.** The console prints *Finished aether-bootstrap.service*
   and *Started aether-ops.service* when it is done, about ten minutes after boot.

   <Image src={console} alt="Console showing aether-bootstrap.service finished and aether-ops.service started" />

4. **Log in** at the console prompt as user `aether`.

   <Aside type="danger" title="The console password does not work in ISO 0.1.0">
   The image was built with user `aether` and, according to its README, password `aether`. On the
   0.1.0 image the stored password hash does not match `aether` (or any obvious variation), so the
   console login is refused, and the same mismatch means the management service cannot reach the
   node over SSH either: deployments started from the web UI fail at the preflight step.

   Until a rebuilt image fixes the hash, set a working password from a recovery shell: reboot, hold
   Shift or press Esc at the firmware splash to get the GRUB menu, edit the Ubuntu entry, append
   `init=/bin/bash` to the `linux` line, boot, then run `mount -o remount,rw /` and `passwd aether`
   with the password `aether` (the value the management service was told to use), then
   `sync` and `reboot -f`. Keep that password until you have read the note on the OnRamp password
   in [How the ISO works](/docs/iso/how-the-iso-works/), because the service uses it too.
   </Aside>

</Steps>

## Verify

Once you have a shell on the node:

```bash
systemctl is-active aether-bootstrap rke2-server aether-ops
ls /var/lib/aether/
cat /etc/aether/network.conf
curl http://localhost:8186/healthz
```

```text title="Expected output"
inactive
active
active
bootstrap.done
TOPOLOGY=collapsed
MGMT_IFACE=enp0s2
N2_IFACE=enp0s2
N3_IFACE=enp0s2
N6_IFACE=enp0s2
{"status":"healthy","version":"v0.4.5","uptime":"3m12s"}
```

`aether-bootstrap` reads *inactive* once it has run; `rke2-server` shows *activating* for a minute
or so after any reboot. `bootstrap.done` replaces the bundle when the bootstrap succeeds, and
`network.conf` records what the setup screen chose. `aether-ops` reports the version
embedded in the ISO's bundle, which may be older than the current release; see the note on the
[install page](/docs/iso/install/).
